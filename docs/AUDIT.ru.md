**Что уже сделано хорошо**

- Токены отделены от данных интерфейса; используются явные DTO и AES-256-GCM с ключом в системном хранилище. Это хорошая основа, хотя миграция старых данных имеет дефекты из топа ниже.
- Есть атомарная запись, резервные копии, восстановление состояния, защита от применения части устаревших результатов и блокировки обновления одного аккаунта.
- OAuth использует PKCE и случайный state. Callback ограничен loopback, проверяет запросы, имеет лимиты размеров и времени.
- Обновление проверяет подпись Minisign ключом из сборки, повторно проверяет скачанный файл и ожидает подтверждение запуска новой версии.
- UI разделён на компоненты, hooks и utils; есть очередь сохранения настроек, события backend, восстановление данных при возврате фокуса, общий таймер и ленивое подключение части экранов.
- В проекте есть содержательные тесты и CI для Windows/macOS. В выбранных 12 существующих тестах ошибок не было; проблема в том, какие аварийные сочетания они пока не проверяют.

**Топ проблем и эффект исправлений**

1. **P1 — после миграции остаются незашифрованные токены. По коду.**

   При переносе старого хранилища `CodexAccountManagerLite` новый vault шифруется, но исходный state и его backup только переименовываются в карантинные файлы. Их содержимое с OAuth-токенами сохраняется. Шифрование нового файла не защищает эти старые копии. Основание: [storage.rs:374](</C:/WORK/Codex Projects/SwitchAI Account Manager/src-tauri/src/storage.rs:374>), функция карантина [storage.rs:116](</C:/WORK/Codex Projects/SwitchAI Account Manager/src-tauri/src/storage.rs:116>).

   **Исправление:** после подтверждённой миграции очищать поля токенов в старых копиях либо сохранять архив зашифрованным. **Плюс:** закрывается конкретный путь хранения credentials открытым текстом. **Минус:** старой версии приложения будет сложнее восстановиться из такого архива. **Проценты:** цель — **−100% незашифрованных токенов в этих управляемых приложением legacy-копиях**; это не относится к резервным копиям пользователя и не означает +100% общей безопасности.

2. **P1 — старый backup может заменить актуальные refresh tokens. По коду.**

   Сначала токены восстанавливаются из plaintext `.bak`, затем выполняется их миграция в vault, и только после этого читается vault. Современный state токенов не содержит, поэтому старый backup выглядит как нужный источник. Точный триггер: рядом с современным state осталась или была восстановлена старая plaintext `.bak`, а vault уже содержит более новые токены. При таком сочетании запуск способен записать устаревшие credentials поверх актуальных. Обычный успешный commit также обновляет backup, поэтому это не утверждение о каждом запуске после миграции. Основание: [storage.rs:311](</C:/WORK/Codex Projects/SwitchAI Account Manager/src-tauri/src/storage.rs:311>), [storage.rs:217](</C:/WORK/Codex Projects/SwitchAI Account Manager/src-tauri/src/storage.rs:217>), [storage.rs:245](</C:/WORK/Codex Projects/SwitchAI Account Manager/src-tauri/src/storage.rs:245>).

   **Исправление:** читать защищённое хранилище первым; использовать legacy-токены только для отсутствующих записей. **Плюс:** предотвращается откат авторизации на старые токены. **Минус:** потребуется явно учитывать частично завершённую миграцию. **Проценты:** цель — **100% сохранение актуальных vault-записей** при наличии устаревшего backup; частота такой ситуации у пользователей неизвестна.

3. **P1/P2 — восстановление vault имеет два тупиковых сценария. По коду.**

   Если основной `secrets.vault.json` отсутствует, код возвращает пустое хранилище, даже если исправный `.bak` существует. После повторного входа создаётся неполный vault; последующие записи способны заменить им хорошую резервную копию. Если основной файл существует, но потерян системный ключ или повреждены обе копии, UI предлагает повторный вход. Однако его сохранение снова читает неисправный vault и завершается той же ошибкой. Основание: [secret_store.rs:248](</C:/WORK/Codex Projects/SwitchAI Account Manager/src-tauri/src/secret_store.rs:248>), [secret_store.rs:317](</C:/WORK/Codex Projects/SwitchAI Account Manager/src-tauri/src/secret_store.rs:317>), [storage.rs:270](</C:/WORK/Codex Projects/SwitchAI Account Manager/src-tauri/src/storage.rs:270>).

   **Исправление:** восстанавливать backup и при отсутствии primary; для невосстановимого vault предложить отдельное пересоздание с сохранением списка аккаунтов и настроек. **Плюс:** пользователь получает рабочий путь восстановления. **Минус:** утраченный ключ не позволяет расшифровать старые токены — понадобится новый вход; backup может содержать уже устаревшие токены. **Проценты:** целевое покрытие — **2/2 описанных аварийных сценария, 100%**; процент автоматически восстановленных действительных сессий заранее неизвестен.

4. **P1 — откат обновления может вернуть неправильную версию. Воспроизведено на Windows.**

   Если прежний `.old` заблокирован, `atomic_swap` сохраняет текущую хорошую версию под другим именем. Но дальнейший rollback продолжает использовать исходный `.old`. В проверке `current=v1`, старый backup `v0`, обновление `v2`: после неудачи обновления функция отката вернула успех, восстановив **v0 вместо v1**. При сохраняющейся блокировке возможна ошибка отката. Основание: [portable_updater.rs:617](</C:/WORK/Codex Projects/SwitchAI Account Manager/src-tauri/src/portable_updater.rs:617>), [portable_updater.rs:645](</C:/WORK/Codex Projects/SwitchAI Account Manager/src-tauri/src/portable_updater.rs:645>), вызовы из helper на строке 835.

   **Исправление:** возвращать из swap фактический путь резервной копии и использовать его во всех ветках восстановления. **Плюс:** откат возвращает именно последнюю рабочую версию. **Минус:** нужно изменить контракт swap/helper и проверить блокировки файлов. **Проценты:** цель — **100% правильных откатов в воспроизведённой ветке**; вероятность этой блокировки на обычных установках не измерена.

5. **P1 — фоновое обновление Gemini может отменить ручную смену аккаунта в Antigravity. По коду.**

   SwitchAI считает активным аккаунт A. Пользователь входит в B непосредственно в Antigravity. При следующем обновлении токенов A менеджер проверяет только свой снимок в памяти и записывает A во внешнюю авторизацию. Внешняя credential читается для возможного отката, но не для проверки личности перед записью. Основание: [gemini/quota.rs:660](</C:/WORK/Codex Projects/SwitchAI Account Manager/src-tauri/src/providers/gemini/quota.rs:660>), [gemini/quota.rs:733](</C:/WORK/Codex Projects/SwitchAI Account Manager/src-tauri/src/providers/gemini/quota.rs:733>). Полная сверка внешней сессии есть при старте приложения.

   **Исправление:** перед фоновой записью сверять внешний аккаунт и версию credentials; при изменении сохранять выбор пользователя. **Плюс:** исчезает неожиданное переключение обратно. **Минус:** больше чтений внешнего хранилища и правил разрешения конфликтов. **Проценты:** цель — **0% перезаписей чужой текущей сессии** в таком сценарии; общий процент ошибочных переключений неизвестен.

6. **P1/P2 — паузы после ошибок API работают не во всех ветках. Частично воспроизведено.**

   Первая проблема: прошедший `reset_at` возвращает `now` раньше сохранённого backoff. Если обновление завершилось ошибкой, старая квота остаётся и планировщик снова назначает выполнение через секунду. Harness получил `1000000` вместо ожидаемого `1005000`. Вторая: `Retry-After` присутствует в HTTP-ошибке, но затем она превращается в строку и `Ok { succeeded: false }`. Планировщик получает серверную задержку только из внешнего `Err`, поэтому обычный 429 теряет её. Основание: [auto_refresh.rs:789](</C:/WORK/Codex Projects/SwitchAI Account Manager/src-tauri/src/auto_refresh.rs:789>), [auto_refresh.rs:545](</C:/WORK/Codex Projects/SwitchAI Account Manager/src-tauri/src/auto_refresh.rs:545>), [refresh_service.rs:334](</C:/WORK/Codex Projects/SwitchAI Account Manager/src-tauri/src/refresh_service.rs:334>).

   **Исправление:** дать активному backoff приоритет; передавать структурированную ошибку и `retry_after` вместе с результатом. **Плюс:** меньше лишних запросов, корректная реакция на ограничения сервера. **Минус:** после восстановления сервера иногда придётся дождаться назначенной паузы. **Проценты:** в искусственном примере период назначения меняется с 1 до 5000 секунд — **на 99,98% меньше потенциальных запусков**, если пренебречь длительностью запросов. Это расчёт для fixture, не замер реального трафика приложения.

7. **P1 — Windows CI способен скрыть провал промежуточной проверки. Воспроизведена семантика PowerShell.**

   В одном `pwsh`-шаге идут подряд 10 native-проверок: версии, audit, lint, build, тесты и проверки Rust. Их коды завершения по отдельности не проверяются. Успешная последняя команда может скрыть ненулевой код предыдущей. Локальный пример с кодами `7 → 0` завершился успешно даже с `$ErrorActionPreference='Stop'`. Основание: [release.yml:52](</C:/WORK/Codex Projects/SwitchAI Account Manager/.github/workflows/release.yml:52>). GitHub описывает проверку итогового `LASTEXITCODE` в [документации workflow](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#exit-codes-and-error-action-preference).

   **Исправление:** разнести проверки на отдельные шаги либо проверять код после каждого native-вызова. **Плюс:** провал обязательной проверки действительно блокирует релиз. **Минус:** CI станет показывать ранее скрывавшиеся ошибки, которые придётся устранить. **Проценты:** цель — **10/10 проверок с независимым контролем результата**. Сейчас у 9 промежуточных проверок нет такой самостоятельной проверки кода; это не означает, что 90% реальных ошибок уже были пропущены.

Дополнительно строки и Details ожидают ключ `relogin:<id>`, которого OAuth не создаёт: кнопка остаётся активной, а на другой вкладке Add выглядит доступной, но молча игнорируется. Основание: [chatgpt/oauth.rs:471](</C:/WORK/Codex Projects/SwitchAI Account Manager/src-tauri/src/providers/chatgpt/oauth.rs:471>), [oauth/server.rs:346](</C:/WORK/Codex Projects/SwitchAI Account Manager/src-tauri/src/oauth/server.rs:346>), [useOAuthLogin.ts:78](</C:/WORK/Codex Projects/SwitchAI Account Manager/ui/src/hooks/useOAuthLogin.ts:78>), [useAccountRowState.ts:23](</C:/WORK/Codex Projects/SwitchAI Account Manager/ui/src/components/accounts/useAccountRowState.ts:23>).

Долгий сетевой запрос от этого сам не ускорится.
