# Подготовка SwitchAI 1.3.0

Состояние на 14 сентября 2026 года. Версия **не выпущена**; текст [release notes](../RELEASE_NOTES.md) — черновик для обсуждения. Дата релиза не назначена. Публикация, создание тега, push и merge ожидают отдельной команды пользователя.

## Что подготовлено локально

- Версии manifests и lockfiles согласованы: 1.3.0.
- Release notes и оба changelog оформлены в стиле 1.1.0/1.2.0: `What's New`, короткие пункты с выделенными названиями улучшений. README badge теперь показывает последний опубликованный релиз.
- `.gitignore` покрывает сборки, локальные данные, варианты резервных/миграционных файлов токенов, временные файлы, ключи подписи и подписи бинарных артефактов. Проверены 16 исключаемых путей и 6 путей исходников/lockfiles, которые должны оставаться доступными Git. Уже отслеживаемых файлов, попадающих под ignore, не найдено.
- Локальный workflow содержит пять обновлений Actions из PR #2, сохраняет проверки кодов возврата Windows-команд и включает оба файла SHA-256 в assets будущего релиза. Отсутствующие файлы публикации приводят к ошибке.

- Исправлен тестовый HTTP-сервер подписок на Windows: принятый сокет явно переводится в блокирующий режим перед чтением с таймаутом.

## Открытые проблемы перед выпуском

Это результаты проверки кода, а не воспроизведение на пользовательских аккаунтах. Прошедшие unit tests не закрывают эти сценарии.

1. **P1 — восстановление vault при отсутствии основного файла.** `read_vault()` в [secret_store.rs](../src-tauri/src/secret_store.rs) возвращает пустое хранилище до проверки зашифрованного backup. Нужно восстанавливать валидную резервную копию и проверить сохранность токенов при последующих записях.
2. **P1 — ошибка очистки legacy-архива может блокировать загрузку исправных данных.** В [storage.rs](../src-tauri/src/storage.rs) ошибка `finalize_legacy_migration()` передаётся из `load_app_data()` после успешного чтения актуального состояния и токенов. Нужно отдельно обработать сбой очистки, сохранив предупреждение и повторную попытку, и проверить повреждённый/недоступный архив.
3. **P2 — staged update не привязан к показанной версии.** [commands/updater.rs](../src-tauri/src/commands/updater.rs) проверяет наличие staged metadata, а [portable_updater.rs](../src-tauri/src/portable_updater.rs) не сопоставляет её версию с предлагаемым обновлением перед установкой. Проверить сценарий «загружена B, уже объявлена C».
4. **P2 — автоматическое восстановление после сетевой блокировки может ждать до суток.** В [auto_refresh.rs](../src-tauri/src/auto_refresh.rs) заблокированные Codex-аккаунты исключаются из расписания; без других доступных аккаунтов очередь засыпает до 24 часов. Истечение кэша reachability само по себе её не будит.
5. **P2 — рекомендации пока допускают 0% остатка.** UI и трей исключают устаревшие квоты и ошибки, но не нулевой резерв. Поэтому черновик не обещает исключение всех исчерпанных аккаунтов.

[Аудит от 8 сентября](AUDIT.ru.md) описывает исторический снимок 1.2.0. Часть находок уже исправлена; его результаты тестов не являются проверкой текущей 1.3.0.

## Оставшиеся этапы

- Разобрать открытые проблемы выше и добавить проверки аварийных сценариев при их исправлении.
- После разрешённого push пройти актуальный Windows/macOS CI, включая Rust dependency audit и сборку universal macOS. Проверить заявленную минимальную версию macOS.
- На тестовых аккаунтах проверить вход, повторный вход, переключение, внешнюю смену сессии и выход, квоты и восстановление сети.
- Проверить подписанное обновление с опубликованной 1.2.0, успешный запуск и откат при сбое. Исправленный helper находится в новом коде; обновление, инициированное старой 1.2.0, использует старую реализацию до замены приложения. Отдельно проверить обновление, инициированное новой версией.
- Собрать окончательные артефакты, проверить подпись Minisign, `latest.json`, контрольные суммы и загрузку assets. Проверить фактическую Authenticode-подпись перед формулировкой раздела SmartScreen.
- Добавить VirusTotal-ссылку для окончательного Windows binary. Ссылку от 1.2.0 повторно не использовать.
- Обсудить и утвердить release notes, убрать Draft/Unreleased и поставить дату только при подготовке согласованной публикации.
- Выпускать по отдельной прямой команде пользователя.
