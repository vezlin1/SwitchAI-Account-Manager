# Подготовка SwitchAI 1.3.0

Состояние на 14 сентября 2026 года. Пользователь дал команду выпустить 1.3.0; [release notes](../RELEASE_NOTES.md) подготовлены к публикации. Версия **ещё не опубликована**. Дата в changelog подготовлена для текущего выпуска; при переносе публикации её нужно обновить.

Пользователь разрешил создание новой пары ключей, её локальное хранение, push и выпуск. Новая пара создана в игнорируемой папке `.release-keys/`, закрытый ключ зашифрован, пароль сохранён в той же защищённой папке. Оба GitHub Actions secrets настроены; публичный ключ обновлён в приложении. Подробности сопровождения — [RELEASE_SIGNING.md](RELEASE_SIGNING.md). Проверка подписи не отключалась. В assets 1.2.0 обнаружены только EXE и DMG; переход на 1.3.0 требует ручной загрузки, что отражено в release notes.

## Что подготовлено локально

- Версии manifests и lockfiles согласованы: 1.3.0.
- Release notes и оба changelog оформлены в стиле 1.1.0/1.2.0: `What's New`, короткие пункты с выделенными названиями улучшений. README badge теперь показывает последний опубликованный релиз.
- `.gitignore` покрывает сборки, локальные данные, варианты резервных/миграционных файлов токенов, временные файлы, ключи подписи и подписи бинарных артефактов. Проверены 16 исключаемых путей и 6 путей исходников/lockfiles, которые должны оставаться доступными Git. Уже отслеживаемых файлов, попадающих под ignore, не найдено.
- Локальный workflow содержит пять обновлений Actions из PR #2, сохраняет проверки кодов возврата Windows-команд и включает оба файла SHA-256 в assets будущего релиза. Отсутствующие файлы публикации приводят к ошибке.

## Исправленные проблемы восстановления и обновлений

1. **P1 — восстановление vault при отсутствии основного файла: исправлено.** [secret_store.rs](../src-tauri/src/secret_store.rs) читает зашифрованный backup, проверяет его и атомарно восстанавливает основной файл без изменения резервной копии. Последующие записи сохраняют токены других аккаунтов. Пустое хранилище создаётся только при отсутствии обоих файлов; повреждённый/недоступный backup или отсутствующий ключ блокируют запись. Добавлено 7 тестов с mock keyring и временными файлами.
2. **P1 — сбой очистки legacy-архива: исправлено.** [storage.rs](../src-tauri/src/storage.rs) возвращает успешно загруженные данные с предупреждением и повторяет очистку при следующей загрузке. Предупреждение передаётся в интерфейс через startup warnings. Ошибки vault и обязательной записи миграции остаются критическими. Добавлено 4 теста: повреждённый архив, блокировка файла, повторная очистка и сохранность источников при сбое миграции.
3. **P2 — соответствие staged update выбранной версии: исправлено.** Готовность и установка проверяют версию и данные артефакта по актуальному manifest; UI передаёт показанную версию при загрузке и установке. Сценарий «загружена B, предлагается C» требует загрузки C. Параллельные загрузка и установка сериализованы, запоздалое завершение B не заменяет данные C в окне, а helper проверяет идентификатор одобренного stage после выхода родительского процесса. Добавлено 3 теста с проверкой подписанного фиктивного payload, включая замену артефакта и повреждение файла. Реальная установка и перезапуск приложения не выполнялись.

## Открытые проблемы перед выпуском

Это результаты проверки кода, а не воспроизведение на пользовательских аккаунтах. Прошедшие unit tests не закрывают эти сценарии.

4. **P2 — автоматическое восстановление после сетевой блокировки может ждать до суток.** В [auto_refresh.rs](../src-tauri/src/auto_refresh.rs) заблокированные Codex-аккаунты исключаются из расписания; без других доступных аккаунтов очередь засыпает до 24 часов. Истечение кэша reachability само по себе её не будит.
5. **P2 — рекомендации пока допускают 0% остатка.** UI и трей исключают устаревшие квоты и ошибки, но не нулевой резерв. Поэтому черновик не обещает исключение всех исчерпанных аккаунтов.

[Аудит от 8 сентября](AUDIT.ru.md) описывает исторический снимок 1.2.0. Часть находок уже исправлена; его результаты тестов не являются проверкой текущей 1.3.0.

- Собрать окончательные артефакты, проверить подпись Minisign, `latest.json`, контрольные суммы и загрузку assets. Проверить фактическую Authenticode-подпись перед формулировкой раздела SmartScreen.

- Обсудить и утвердить release notes, убрать Draft/Unreleased и поставить дату только при подготовке согласованной публикации.
